# 原 RTS 塔防 Demo：兼容性与品质改进

本轮继续使用 `Main.tscn`、原关卡、全部塔/敌人资源、建造操作、技能、装备、Buff、天赋和原有攻击/移动动画。没有添加替代玩法入口，也没有改动波次编队、价格、奖励、伤害、护甲公式或塔数量限制。原有两处火球材质改动保留。

## 已实现的行为

## 接入约定

- `BaseUnitResource.animation_player_path / animation_tree_path / health_anchor_path`：相对单位根节点的可选NodePath。空值继续使用原资产的兼容查找。
- `building_footprint: Vector2i`：格网X/Z占地，默认(1,1)，上限8×8；没有自动扩大现有塔的占地。多格资产以占地中心放置。
- `anim_ack_normalized`：-1保留秒数；0–1按攻击动画长度与播放速度计算释放延迟。没有批量重定时原攻击。
- `SkillContext.snapshot()`：每次释放的目标、建造对象、回调与交易状态独立保存。
- `PlayerController.validate_skill_cost/commit_skill_cost`：原因字符串/原子提交。通知信号不承担扣费。
- `BaseUnit.do_logical_death(reason)`：只有killed发送全局击杀事件；所有离场均只执行一次。升级保留`unit_uid`，引擎实例ID仍会因模型替换而变化。
- `ItemSystem.transfer_all`：保留现有Item实例、冷却和属性，按现有同类唯一规则处理目标单位默认物品。
- `BaseUnit.receive_damage(context, source_modifiers, target_modifiers)`：公共结算入口；现有take_damage/take_skill_damage继续兼容。
- `WaveManager.cancel_spawning()`：取消不可恢复的旧生成代数；波次推进仍由原资源延迟决定。

Godot 4.7.2下，自引用的导出类型数组会使资源脚本残留。两处等级配置容器改用`Array[Resource]`，加载时验证元素实际为ItemResource/SkillMetaResource；原序列化资源和等级数据不改。仅去掉默认初始化不足以解决本工程的问题。相关引擎问题：[godotengine/godot#122601](https://github.com/godotengine/godot/issues/122601)。

## 2026-10-24：滚屏与框选组合修复

新增失败用例在修复前复现了五类问题：非左键释放提前提交框选、漏收抬键留下状态、暂停时选框残留、命令栏阻断底边滚屏，以及框选与滚屏不能稳定同时工作。旧选择测试关闭镜头，无法覆盖这些组合。

### 输入与兼容接口

- `BattleInput.interaction_available(viewport)` 处理暂停、场景切换、终局、设置和天赋模态状态；`pointer_available(viewport, position)` 保留原接口，按当前事件坐标判断阻挡UI；`edge_scroll_available(viewport, position)` 允许普通HUD边缘滚屏。
- 阻挡战场输入的真实UI根控件加入 `blocks_world_input` 组。判断使用控件的实际画布变换和可见矩形，不使用上一事件的悬停缓存。信息HUD布局穿透鼠标；其中的按钮继续保持交互与阻挡。
- 槽位鼠标操作通过 `_gui_input` 接收，装饰子控件穿透；快捷键通过 `_unhandled_key_input` 处理并检查可见性和模态状态。原槽位点击信号、技能和装备行为保留。
- `SelectionBox` 是唯一手势状态所有者，提供 `is_selecting()` 和幂等 `cancel_selection(reason)`，保留原开始/完成信号。矩形组件仅提供 `show_rect/clear`。旧Area3D节点保持禁用，旧缓存保留兼容清理入口，不承担结果判断。
- 左键释放仅提交一次；右键按下或Esc取消手势，保留之前选择；其他按钮释放不提交。达到6像素后返回起点仍属于拖动。下一条鼠标移动的按钮掩码可发现漏收释放。
- 框选期间继续滚屏：起点固定在屏幕，显示与结果共享同一矩形，按释放时视野中的单位投影中心结算。选择不依赖地表射线旧缓存；原技能/建造仍通过各自目标检查。
- 镜头使用视口鼠标事件坐标、窗口焦点和进出事件，离开边缘立即停，抵达边界清掉向外速度。速度、加速度、角度、地图边界和单位内容没有改动。
- 框选清理在暂停期间仍执行；打开设置、离开默认操作模式、终局与场景切换在禁用/释放节点前主动取消。失焦、移出窗口、调整视口尺寸也取消，不自动恢复旧手势。

### 回归覆盖和限制

`selection-input` 扩展为69项断言，使用视口事件链，包含四方向拖框、八方向滚屏、显示命令栏后的向下滚屏、镜头边界反向移动、滚屏时两塔实际框选、GUI头像点击、右键交错、Esc、漏收抬键、暂停、窗口焦点/移出信号、设置、操作模式、调整尺寸、20次取消及拖动中重开。调整实际运行窗口为1280×720、1920×1080、1280×800、2560×1080，检查透明HUD区域仍可开始战场手势。

窗口焦点和移出采用窗口信号注入；这些检查验证游戏的响应逻辑，不替代编辑器嵌入窗口、系统Alt-Tab、多显示器/DPI的真实鼠标人工验收。当前未声称这些人工场景已经通过。编辑器立即退出时已有的资源清理/语言服务告警与运行包检查分开记录，不能混同为战斗退出泄漏。

## 2026-10-24：鼠标限制与持续边缘滚屏

根因：此前滚屏入口同时要求`pointer_inside`和视口内坐标，`mouse_exited`又直接清零速度。快速推向边缘并越界后必然停止。现在战斗默认采用Godot原生`MOUSE_MODE_CONFINED`，可见光标停在窗口边缘继续滚屏；技能/天赋隐藏光标时使用`MOUSE_MODE_CONFINED_HIDDEN`。没有采用窗口外无限滚屏，也没有在游戏帧中强制传送鼠标。

`Main`持有`BattleCursor`，统一管理正式战斗的鼠标模式。技能/天赋通过`request_hidden(owner, hidden)`请求显示或隐藏，通过`release_owner(owner)`释放；请求用弱引用按来源记录。多个来源互不覆盖，节点销毁、取消目标设置及会话清理不会遗留隐藏请求。延迟目标指示取消后不再重新隐藏光标。

- **F2**临时释放或恢复；再次点击战场也可恢复。恢复点击在事件链和轮询判断中屏蔽一帧，不误触发选择、建造或施法。临时释放不保存到配置。
- 失焦立即解除限制、取消手势并停止镜头；重新获焦不直接重新锁住鼠标，需要点击游戏区域或F2，避免标题栏操作重新捕获。
- 设置、天赋选择、暂停、终局、菜单和退出均解除限制；战斗恢复且鼠标在游戏区域内时恢复限制。解除期间真正移出窗口会使缓存位置失效，不用旧边缘坐标继续滚屏。
- 原生限制仍有效时，边缘/遮挡产生的`mouse_exited`不再单独中断滚屏和框选；真正失焦/释放仍停止。镜头边界坐标在视口有效范围内钳制，普通HUD继续不阻断滚屏。

Windows原生专项38项断言、无界面状态专项19项断言。原选择专项中“限制生效时移出信号必然停止”的旧断言已按新规则调整，保留失焦、暂停、模态、模式切换及释放后的停止验证。
